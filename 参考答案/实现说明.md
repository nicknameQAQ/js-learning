# 参考答案实现说明

建议自己做完相应阶段后再读。这里讲设计，不需要逐字照抄答案。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| web/index.html | 表单、筛选、表格与提示区域 |
| web/style.css | 桌面 / 手机布局与样式 |
| web/src/domain.js | 数据校验、金额转换、查询分页与增删改的纯数据逻辑 |
| web/src/storage.js | localStorage 读写与损坏检测 |
| web/src/api.js | fetch 请求、统一错误处理和 204 处理 |
| web/src/main.js | 页面状态、事件绑定、渲染与调用保存层 |
| server.mjs | 静态资源、本地 HTTP 接口、JSON 文件保存 |
| tests/ | 数据、保存、接口与浏览器行为检查 |

## 一次新增发生了什么

1. submit 事件阻止浏览器默认刷新。
2. 从输入框读取字符串、复选框读取 boolean。
3. 把“元”转换成整数“分”，校验所有字段。
4. 保存层生成 id 并保存数据。
5. 成功后清空表单，再查询一次列表。
6. 失败时显示错误，保留输入；finally 恢复按钮。

对照 Java：domain 像 Service 中的数据规则，保存层像 Repository。
JS 的 async 函数返回 Promise。await 暂停的是当前异步函数，不是整个浏览器。

## 为什么给两种保存层相同的方法

页面只调用 list / get / add / update / remove / reset。
切换 localStorage 和 HTTP，只换 repository，表单和表格不用再写一遍。
以后接 Java 后端，按接口文档实现同一协议，或在 api.js 做响应格式适配。

## 为什么金额用整数分

二进制浮点不能精确表示某些十进制小数。
答案将文本拆成整数元和小数部分，拼成整数分；显示时再格式化。
0 元图书合法，不能用 truthy 判断它有没有填写。

## 为什么搜索还要请求序号

AbortController 可以取消多数未完成请求，但不保证所有异步处理都立刻结束。
请求序号让页面只接受最新查询。即使旧请求忽略取消，也不能覆盖新结果。
本地查询也使用同样的页面入口，不为两种模式维护两套交互代码。

## 为什么损坏数据不直接清空

损坏不代表原数据没有价值。
本地模式保留原字符串并提示，用户确认重置后才替换。
服务端数据文件损坏则拒绝启动；不要用重新初始化把问题掩盖掉。

## 为什么服务器写文件要排队

同一时间的两次新增，必须生成不同编号。
单进程按队列执行写操作，先复制数据、写临时文件、替换成功，再更新内存。
写入失败时旧内存仍在，后续写请求也能继续。
这是本地练习的持久化方式，不是数据库事务的替代方案。
